# CONTEXT.md 维护规范

## 什么是 CONTEXT.md

`artifacts/CONTEXT.md` 是项目的知识仓库。它记录了所有 Agent 需要知道的持久信息，确保"不会做了后面忘了前面"。

## 谁维护

| 操作 | 负责Agent | 时机 |
|------|----------|------|
| 创建 | Orchestrator | 项目启动时 |
| 添加架构决策 | Architect | ADR 确定后 |
| 更新文件职责 | Dev (后端/前端) | 创建/修改文件后 |
| 更新功能状态 | Dev (后端/前端) | 功能完成后 |
| 审查一致性 | Reviewer | 审查时 |
| 最终化 | PM | Sprint 2 |

## 格式

```markdown
# <项目名> · 项目上下文

## 架构决策记录 (ADR)
- ADR-001: 标题（理由）[日期]
- ADR-002: 标题（理由）[日期]

## 已完成功能
- [x] 功能名: 实现位置 | 负责Agent | 日期

## 功能依赖关系
- 功能A → 依赖于功能B的某个输出

## 文件职责
| 文件 | 职责 | 最后修改Agent |
|------|------|--------------|

## 当前Sprint状态
- 正在进行的TASK: TASK-NNN
- 阻塞项: 无
```

## 规则

1. **读前写后** — 修改代码前必须读 CONTEXT.md，修改后必须更新 CONTEXT.md
2. **只追加不删除** — ADR 历史不能删除，只能追加新的
3. **记录变更原因** — 如果修改了别人写的代码，在 CONTEXT.md 中注明原因
4. **依赖关系必须记录** — 如果功能A依赖功能B，必须在 CONTEXT.md 中写明
